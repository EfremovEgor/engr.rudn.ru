# Ревью проекта и реструктуризация

Документ описывает найденные проблемы и то, как они решены.

## Безопасность

| Проблема | Решение |
| --- | --- |
| `SECRET_KEY` хранился в репозитории | ключ из `DJANGO_SECRET_KEY`; без него сайт в боевом режиме не стартует. **Ключ на проде нужно сменить** |
| `ALLOWED_HOSTS = ["*"]` | список хостов из окружения |
| `admin_utilities/update_study_profiles` — без проверки прав: любой, кто знает адрес, мог удалить все программы и загрузить свои | страница удалена |
| Rosetta по публичному адресу `/rosetta/` | перенесена под секретный адрес админки |
| CKEditor 4 (django-ckeditor) — версия без поддержки, с известными уязвимостями | CKEditor 5 |
| `settings.py` в `.gitignore` при этом лежал в репозитории — настройки прода могли расходиться с кодом | настройки в репозитории, все параметры окружения — в `.env` |
| Нет защищённых cookie за HTTPS, нет `SECURE_PROXY_SSL_HEADER` | добавлены (включаются переменной `DJANGO_SECURE_COOKIES`) |
| Имя тэга подставлялось в inline-JS (`onclick="...'{{ tag.name }}'"`) | ссылки вида `?tag=` без JS |
| Загрузка файлов любого типа | медиатека запрещает html/js/php/исполняемые файлы, есть лимит размера |

## Ошибки

- На английской версии страницы кафедры не показывали программы, а «Дни открытых дверей» — презентации:
  фильтр шёл по переведённой строке (`_("Бакалавриат")`, `_("Презентация")`).
- У заочной формы обучения выводилось количество бюджетных мест очно-заочной.
- `?prog_lang=<любой другой язык>` на странице программ — ошибка 500.
- Семинар без докладов или доклад без докладчика — ошибка 500 (`get_reports`, `is_past_due`).
- `SeminarReport.speaker` имел `default="profile_default.png"` — создание доклада без докладчика падало.
- Удаление сотрудника удаляло все семинары, где он председатель или организатор;
  удаление докладчика удаляло его доклады (`on_delete=CASCADE`).
- Обложка новости пережималась (с искажением пропорций до 600×450) при **каждом** сохранении новости,
  каждый раз создавая новый файл.
- Ссылка `/profile/<id>/` со слэшем (со страницы научных центров) давала 404.
- Плейсхолдер `ym(YYYYYY, …)` в счётчике Метрики вызывал ошибку JS на каждой странице.
- CSV-импорт записывал языки кодами `ru`/`en`, а сайт ожидал «Русский»/«Английский» —
  такие программы не попадали в фильтр по языку.
- 26 строк интерфейса в `.po` были помечены fuzzy (и показывались по-русски на английской версии),
  «Русский» был переведён как «Spanish».
- `requirement.txt` был в UTF-16, без версий, с дублирующимися пакетами (`psycopg2` и `psycopg2-binary`),
  а `seminars/views.py` импортировал не указанный в зависимостях `requests`.

## Архитектура и база данных

**Сервисы.** Приложение `pages` содержало почти все модели. Теперь модели разнесены по приложениям
`academy`, `education`, `science`, `seminars`, `profiles`, `news`, `documents`, `pages`, `media_library`,
общий код — в `core`. Перенос сделан без пересоздания таблиц: модели сначала переносятся только в состоянии
Django (`SeparateDatabaseAndState`), затем таблицы переименовываются (`AlterModelTable`), ContentType и права
переносятся — права групп и история админки сохраняются.

**Переводы.** Вместо ручных полей `*_en` и проверок `{% if LANGUAGE_CODE == 'en' and x.name_en %}` в шаблонах —
django-modeltranslation: поля `<поле>_ru`/`<поле>_en`, `{{ x.name }}` сам выбирает язык и откатывается на
русский. Английские версии добавлены и тем моделям, у которых их не было (программы ДПО, оборудование,
партнёры, студкомитет, контакты на главной и др.).

**Структура данных.**

| Было | Стало |
| --- | --- |
| `Profile` + 3 FK на `ProfileDetails` (очная/очно-заочная/заочная) | `Program` → `ProgramOffer` (FK + форма обучения), редактируются вместе |
| Минимальные баллы — два JSON-поля с русскими ключами | `OfferExam` (предмет, бюджет, контракт) + справочник `ExamSubject` с переводом |
| `StudyDirection.profiles` many-to-many | `Program.direction` (FK) |
| Уровни и языки — русские строки (частично коды) | коды `bachelor`/`specialist`/`master`/`postgraduate`, `ru`/`en` |
| `Seminar.reports` many-to-many, `chair1`/`organizer1` | `SeminarReport.seminar` (FK), `chair`/`organizer` |
| `NewsItem.tags` и `tags_en` на одну модель тэгов | одна связь, тэг с переводимым названием |
| 4 одинаковые модели документов | `Document` с полем «Раздел» и файлом для каждого языка |
| Адреса кафедр и шаблоны центров — словари в `aliases.py` | поля `slug` и `legacy_template` в БД |
| Слайдер: 4 поля изображений | 2 переводимых поля изображения |

**Данные при миграции не удаляются.** Особые случаи выводятся в лог миграции:
- профиль в нескольких направлениях — остаётся в первом;
- условия приёма, общие для нескольких программ, — копируются;
- доклад в нескольких семинарах — копируется с новым адресом, старый адрес перенаправляет на основную копию;
- условия приёма и доклады без привязки остаются, их видно через фильтры в админке.

Миграции проверены на копии базы со старой схемой и данными (включая перечисленные краевые случаи),
на пустой базе и автотестом `apps/core/tests/test_migrations.py`.

## Админка (django-unfold)

- Меню по задачам редактора, панель управления со статистикой и быстрыми действиями.
- Единые формы: общие поля сверху, языковые вкладки ниже; под английскими полями — русский оригинал.
- Колонка и фильтр «Перевод EN» во всех списках, страница «Переводы контента» со ссылками на непереведённое.
- Связанное редактируется вместе: условия приёма — в программе, баллы — в условиях, доклады — в семинаре,
  программы — в направлении.
- Сортировка перетаскиванием, публикация/скрытие без удаления, автодополнение связей, превью изображений.
- Медиатека: загрузка перетаскиванием, папки, копирование ссылки, «где используется»,
  вставка в текст из редактора, удаление файла с диска только если он не используется.

## Инфраструктура

- Сайт в Docker (gunicorn + whitenoise), Postgres и nginx на хосте, миграции при старте контейнера.
- Удалены Prometheus и Grafana (включая подмену движка БД `django_prometheus`).
- Удалён django-compressor (whitenoise сжимает статику при сборке образа).
- Зависимости с зафиксированными версиями, Django 5.2 LTS.
- `sitemap.xml`, `/healthz` для проверки работоспособности.

## Что стоит сделать дальше

- Перенести тексты свёрстанных страниц (история, приёмная комиссия, научные центры и т. д.) в модель `Page`
  или в поле «Подробное описание» центров — тогда их можно будет править без программиста.
  Для научных центров механизм уже есть: как только заполнено описание, используется оно, а не старый шаблон.
- Перенести ~85 МБ изображений и видео из `static/` в медиатеку.
- Меню сайта (шапка) сейчас в шаблоне — можно сделать редактируемым.
- `static/js/seminars.js` обращается к несуществующему адресу `/science/seminar/<id>/get_reports`
  (опечатка была и раньше) — календарь докладов фактически не работает.
- Настроить резервное копирование БД и `src/uploads` по расписанию (`make backup`).
